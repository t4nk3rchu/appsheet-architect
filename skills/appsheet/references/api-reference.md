# AppSheet REST API Reference

Comprehensive specification for invoking AppSheet REST API endpoints, authenticating requests, performing CRUD operations, and configuring webhooks.

---

## 1. Overview & Base Endpoint

The AppSheet API allows external systems (backend services, Cloud Functions, Zapier, Make, Postman) to query, insert, update, and delete records in AppSheet apps.

### Base Endpoint URL
```http
POST https://www.appsheet.com/api/v2/apps/{appId}/tables/{tableName}/Action
```

- Regional hosts (Enterprise Plus data residency): `eu.appsheet.com`, `asia-southeast.appsheet.com`. `api.appsheet.com` is still supported but deprecated.
- **Plan requirement:** the official page states the API is supported for Enterprise plans only. No rate limits are documented.
- URL-encode table names that contain spaces or special characters.

- **`{appId}`**: Unique application ID (found in AppSheet Editor under *Settings > Integrations*; label may vary by editor version).
- **`{tableName}`**: The target table name as defined in the AppSheet data model.

---

## 2. Authentication & Headers

All requests must be sent via `POST` with the following HTTP headers:

```http
Content-Type: application/json
ApplicationAccessKey: V2-AbCdEf1234567890XYZ...
```

The key may also be sent as a query parameter (`?applicationAccessKey=...`), which is less secure; if both are present, the header wins.

> **Security Note:** Application access keys should be generated under *Settings > Integrations* and kept confidential in secret managers or environment variables.

## 3. Supported Actions

| Action | Description | Required Parameters |
| :--- | :--- | :--- |
| **`Add`** | Inserts one or more new records | `Rows` (array of row objects) |
| **`Edit`** | Updates existing records matching the key column | `Rows` (array of row objects containing Key) |
| **`Delete`** | Deletes records matching the specified keys | `Rows` (array of objects containing Key) |
| **`Find`** | Queries and retrieves records | `Selector` (in `Properties`; omit for all rows) |
| *Action name* | Runs an existing data-change action defined on the table | `Rows` |

There is no `AddOrUpdate` action. The `Add` page documents only that the new row's key must be supplied or generated by the key column; upsert behavior is unverified, so use `Find` then `Add`/`Edit`.

## 4. Request Payload Schema

```json
{
  "Action": "Add",
  "Properties": {
    "Locale": "en-US",
    "Location": "47.623098, -122.330184",
    "Timezone": "Pacific Standard Time",
    "RunAsUserEmail": "auditor@example.com",
    "UserSettings": {
      "Department": "Operations"
    }
  },
  "Rows": [
    {
      "OrderID": "ORD-1001",
      "Customer": "Acme Corp",
      "OrderDate": "2026-08-28",
      "Status": "Pending",
      "Total": 1450.00
    }
  ]
}
```

### Properties Object Fields
- **`Locale`** *(string)*: Client locale for formatting (e.g. `"en-US"`).
- **`Timezone`** *(string)*: Timezone string for date/time resolution (default UTC).
- **`Location`** *(string)*: Client latitude/longitude (default `0.000000, 0.000000`).
- **`RunAsUserEmail`** *(string)*: User the action runs as (default: app owner).
- **`UserSettings`** *(object)*: Key-value map mimicking active user settings.
- **`Selector`** *(expression)*: For `Find`; see section 5.4. Not supported for `Delete` (community-reported).

## 5. Action Examples

### 5.1 `Add` (Insert Rows)
```json
{
  "Action": "Add",
  "Properties": {
    "Locale": "en-US",
    "Timezone": "UTC"
  },
  "Rows": [
    {
      "ProductID": "PROD-99",
      "Name": "Wireless Sensor",
      "UnitPrice": 49.99,
      "InventoryCount": 200
    }
  ]
}
```

### 5.2 `Edit` (Update Existing Rows)
```json
{
  "Action": "Edit",
  "Properties": {
    "Locale": "en-US"
  },
  "Rows": [
    {
      "ProductID": "PROD-99",
      "UnitPrice": 44.99,
      "InventoryCount": 185
    }
  ]
}
```

### 5.3 `Delete` (Delete Rows)
```json
{
  "Action": "Delete",
  "Rows": [
    {
      "ProductID": "PROD-99"
    }
  ]
}
```

### 5.4 `Find` (Query Rows with Selector)
```json
{
  "Action": "Find",
  "Properties": {
    "Selector": "Filter(Products, [UnitPrice] > 30.00)"
  },
  "Rows": []
}
```

## 6. Response Schema & Status Codes

### Success Response (`200 OK`)
The official page documents no response body. Row data is shown below as an example; add/edit responses are commonly wrapped as `{"Rows":[...]}` (community-reported), so inspect the real response.

The official page documents no response body. Row data is shown below as an example; add/edit responses are commonly wrapped as `{"Rows":[...]}` (community-reported), so inspect the real response.

```json
[
  {
    "ProductID": "PROD-99",
    "Name": "Wireless Sensor",
    "UnitPrice": 44.99,
    "InventoryCount": 185,
    "_RowNumber": 12
  }
]
```

### Common HTTP Status Codes

- **`200`**: Success.
- **`400`**: Access key or App ID missing, or invalid POST body.
- **`403`**: Web API not enabled for the app, or access key invalid.
- **`404`**: App not found.
- **`500`**: Unexpected error.

No `401` is documented. Mismatched keys are rejected and logged to the audit history.

## 7. Webhook Integrations

### Outbound Webhooks (from AppSheet Bots)
AppSheet bots can trigger HTTP requests to external endpoints on row events:
- **URL**: `https://api.yourdomain.com/v1/webhook`
- **HTTP Method**: `GET`, `GET`, `POST`, `PUT`, `PATCH`, or `DELETE`
- **HTTP Headers**: Custom authorization headers (e.g. `Authorization: Bearer <token>`)
- **Body Template**:
  ```json
  {
    "event": "ORDER_CREATED",
    "order_id": "<<[OrderID]>>",
    "customer": "<<[CustomerID].[Name]>>",
    "total": <<[Total]>>,
    "timestamp": "<<NOW()>>"
  }
  ```
